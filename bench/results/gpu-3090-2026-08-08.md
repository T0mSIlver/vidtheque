# RTX 3090 — backend matrix and lifecycle validation (2026-08-08)

First run of the worker on real GPU hardware. Every number below came through
the HTTP endpoints of a `DEVICE=cuda` worker, with device VRAM sampled from
`nvidia-smi` at 500 ms and the manager's own `/status` at 250 ms on one clock.
Driver: `bench/gpu_validation.py`; raw JSON per check in `raw/`.

| | |
|---|---|
| GPU | NVIDIA GeForce RTX 3090, 24576 MiB, driver 550.163.01, CUDA 12.4 |
| torch | 2.8.0+cu128 · transformers 4.57.6 · sentence-transformers 5.7.0 · onnxruntime 1.28.0 |
| worker env | `DEVICE=cuda`, otherwise `deploy/.env.example` defaults |
| STT input | `youtu.be/dNRDvLACg5Q` — Computerphile, *Turing Machines Explained*, 324.4 s, English, opus |
| warm STT input | `youtu.be/5C_HPTJg5ek` — Fireship, *Rust in 100 Seconds*, 148.6 s |
| frames | the 44 keyframes the CPU smoke cut from the Fireship clip, 1280 px JPEG |
| idle TTL | `IDLE_UNLOAD_SECONDS=15` for the decay checks, `0` where a check needs models pinned |

**All VRAM figures are `nvidia-smi memory.used` for the whole device.** NVML —
what the worker itself reads, and what admission control gates on — reports
322 MB *more* used than `nvidia-smi` on this card, constant, driver reserve.
The two are never mixed in one number here.

## 1. Backend matrix

Load times are the worker's own (`loaded <task> … in Ns`, measured around
`backend.load()`), weights already in the HF cache. "reload" is the same load
after an idle unload, with the OS page cache warm.

| backend | model | load | reload | VRAM loaded, idle | VRAM peak, inference | throughput |
|---|---|---|---|---|---|---|
| whisperX | large-v3 fp16, batch 16, align on | **5.8 s** | 2.5 s | **4993 MB** | **7941 MB** (324 s clip) · 7137 MB (149 s) | **49.9x** realtime (inference only) · 26.4x incl. load · 43.2x warm |
| Qwen3-Embedding | 0.6B fp16, 1024-d | **6.8 s** | 3.7 s | **1975 MB** | 1975 MB (batch 64 × 575 chars) | **200 embeddings/s** · single query 15 ms |
| SigLIP 2 | so400m NaFlex bf16, 1152-d, 256 patches | **6.9 s** | 5.8 s | **2867 MB** | 2870 MB (44 frames/request) | **103 frames/s** · frame-query 9.9 ms (3 queries) |
| RapidOCR | PP-OCR ONNX, CPU | 0.5 s | — | **0 MB** | **0 MB** | 3.4 frames/s, 419 lines over 44 frames |

Notes on the ones that need them:

- **whisperX** downloads 2.9 GB of `Systran/faster-whisper-large-v3` on first
  load: that load took **14.3 s** including the fetch. The wav2vec2 alignment
  model (360 MB) downloads on first *inference*, not on load — it is part of
  the 4993 MB idle figure, not of the 3.3 GB the CTranslate2 model alone takes.
- **Word timestamps land**: 766 words on the 324 s clip, 766 of them with
  `start`/`end`/`score`. First word `{"word": "Back", "start": 0.331, "end":
  0.532, "score": 1.0}`.
- **Both SigLIP towers share one load.** After 9 image batches and 32
  frame-query batches, `/status` reports `image_embed` `load_count: 1`,
  `job_count: 41`. `/v1/embeddings/frame-query` returns 1152-d vectors from the
  same slot — no second model, no second load.
- **RapidOCR never touches the card**: device VRAM is 2 MB before, during and
  after a 44-frame OCR request, and the worker never creates a CUDA context at
  all in an OCR-only process.

### STT batch size

| `STT_BATCH_SIZE` | VRAM peak (324 s clip) | idle loaded | realtime factor (inference only) |
|---|---|---|---|
| 16 (default) | 7941 MB | 4993 MB | 49.9x |
| 4 | 5352 MB | 4961 MB | 40.3x |

Batch size buys ~24% throughput for ~2.6 GB of peak. Neither setting comes
anywhere near the backend's 3200 MB estimate — see §4.

## 2. The core assertion: does the VRAM come back?

Per backend: load on demand, go idle, wait out `IDLE_UNLOAD_SECONDS=15`, watch
the device.

| backend | before load | loaded | after idle unload | returned to |
|---|---|---|---|---|
| whisperX | 2 MB | 4993 MB | **343 MB** | CUDA context floor |
| Qwen3-Embedding | 2 MB | 1975 MB | **339 MB** | CUDA context floor |
| SigLIP 2 | 2 MB | 2869 MB | **339 MB** | CUDA context floor |
| RapidOCR | 2 MB | 2 MB | 2 MB | — (never allocated) |

**The 337–341 MB that does not come back is the CUDA primary context**, created
by the first `.to("cuda")` and released only when the process exits — measured
`after_process_exit_mb: 2` in every check. It is not model memory and no
`empty_cache()` can free it.

The leak test that matters is therefore the *second* cycle, against that floor:

| backend | floor after cycle 1 | floor after cycle 2 | growth |
|---|---|---|---|
| whisperX | 343 MB | 343 MB | **0 MB** |
| Qwen3-Embedding | 339 MB | 339 MB | **0 MB** |
| SigLIP 2 | 339 MB | 339 MB | **0 MB** |

Decay is a step, not a ramp. whisperX, sampled at 500 ms (`t` is seconds since
the check started; last job ended at t=41.7, TTL 15 s):

```
t=55.3  4993 MB      t=57.4  1817 MB      t=58.4  343 MB
t=56.9  4993 MB      t=57.9   343 MB      … flat at 343 MB for the next 75 s
```

The worker logged `unloading stt (idle)` at the 57.4 s sample: **the whole
4.6 GB is back within ~1.1 s of the unload**, and stays back. Same shape for
both embedders (1975 → 339 and 2869 → 339 in one sampling interval).

## 3. Lifecycle under pressure

### Resident exemption (`EMBED_RESIDENT=1`)

Embed, then frame-embed, then OCR; then 50 s of idle against a 15 s TTL.

| | |
|---|---|
| all three loaded | 4029 MB |
| after the reaper | **1485 MB** |
| `embed` loaded / unload_count | **true** / **0** |
| `image_embed`, `ocr` loaded | false, false (`unloading image_embed (idle)`, `unloading ocr (idle)`) |
| cost of residency | **1483 MB** over an empty process (1146 MB of weights + 337 MB context) |

`deploy/.env.example` advertises ~1.8 GB for this. The honest figure on this
card is **1.15 GB of weights, 1.48 GB of device**.

### Sequential queue

One STT request and one 64-chunk embedding request fired 200 ms apart, both
cold:

```
running spans:  stt   [ 1.81 s → 13.85 s ]
                embed [14.13 s → 18.58 s ]
max in-flight: 2      max queue depth: 1      overlap: none
wall clock 16.9 s     sum of request times 28.8 s
```

Two HTTP requests in flight, one GPU job at a time, and the second request's
latency is the first one's wall clock plus its own. That is the manager's
central claim and it holds.

With `IDLE_UNLOAD_SECONDS=0`, both models were still loaded 20 s after the last
job (5495 MB held) — idle unloading is genuinely disabled, not merely slowed.

### LRU eviction under a co-tenant

`bench/ballast.py` holds 13987 MB in a separate process, the way llama.cpp
would. Worker state going in: `embed` loaded (older `last_used`), `stt` loaded,
5753 MB between them, 4212 MB free.

| | |
|---|---|
| requested | `/v1/embeddings/image` (44 frames), estimate 5000 + 512 headroom = **5512 MB needed** |
| free | 4212 MB — does not fit |
| manager did | `unloading embed (vram pressure)` → re-probe → load `image_embed` |
| result | **200 OK**, loaded after: `stt`, `image_embed` |

Evicted the least-recently-used non-resident backend, one at a time, re-probing
between — exactly the specified policy, and it stopped evicting as soon as the
load fitted (`stt` survived).

### The 503 contract

Fresh worker, nothing loaded, 22251 MB of ballast, 1697 MB free:

```
HTTP/1.1 503
Retry-After: 30
{"error": {"type": "insufficient_vram",
           "message": "image_embed needs ~5512 MB (estimate 5000 + headroom 512),
                       1697 MB free and nothing evictable"}}
```

Backends loaded after the refusal: none. Lease held after the refusal: no. The
contract `mcp/`'s retry loop is written against (`VIDTHEQUE_WORKER_RETRIES`,
`Retry-After`) is real.

### Lease hooks

`GPU_ACQUIRE_CMD` / `GPU_RELEASE_CMD` pointed at a stub appending
`<epoch> <event> <nvidia-smi memory.used>`:

```
1786218177.59  acquire    2 MB     <- before the first load; device is empty
1786218204.28  release  345 MB     <- after the last unload; only the CUDA context left
```

- Nothing fired at boot. One `acquire` total, for **two** models (embed, then
  SigLIP 2) — not one per load.
- The `release` line lands after `unloading embed (idle)` and `unloading
  image_embed (idle)`, at the context floor: the card is genuinely free when
  the co-tenant is told it is.
- `/status` `lease.acquired` follows: `true` while anything is loaded, `false`
  after the reaper.

## 4. Where the estimates are wrong

`Backend.vram_estimate_mb` is what admission control gates on. Measured
against it:

| backend | estimate | measured idle | measured peak | verdict |
|---|---|---|---|---|
| whisperX large-v3 | 3200 MB | 4993 MB | **7941 MB** | **2.5x under** at peak, 1.6x under at idle |
| Qwen3-Embedding 0.6B | 1800 MB | 1975 MB | 1975 MB | ~10% under; fine |
| SigLIP 2 so400m | 5000 MB | 2867 MB | 2870 MB | **1.7x over** |
| RapidOCR | 0 MB | 0 MB | 0 MB | exact |

The whisperX gap is not academic. Park a co-tenant so that 4197 MB is free —
above the 3712 MB the gate asks for, below what the job needs:

```
admission control: 4197 MB free ≥ 3200 + 512  ->  load admitted, 6.8 s
inference:         RuntimeError: CUDA failed with error out of memory
response:          500 Internal Server Error   (not 503, no error envelope)
device peak:       24109 MB of 24576
```

and then, with the co-tenant *gone* and 20 GB free:

```
retry:  500  parallel_for failed: cudaErrorInvalidDevice: invalid device ordinal
```

The slot stays `loaded: true` after a failed job, so every later STT request
meets the same poisoned CTranslate2 context. Recovery came only when the idle
reaper unloaded it 15 s later and the next request reloaded — i.e. by accident.
With `IDLE_UNLOAD_SECONDS=0` there is no reaper and the slot never recovers.

Details, repro and suggested fixes: `research/gpu-validation-2026-08-08.md` §5.

## 5. Reproducing

```bash
uv sync --package vidtheque-worker --extra gpu --extra nvml
uv run --no-sync python bench/gpu_validation.py \
    stt embed image_embed ocr resident queue evict no-room hooks hooks-ocr \
    --audio <talk.opus> --audio2 <short.opus> --frames <keyframes-dir> \
    --repeat 8 --idle-ttl 15 --out bench/results/raw
```

Each check is a fresh worker process, so a check can be re-run alone. `evict`,
`no-room` and `stt-underestimate` start `bench/ballast.py`; nothing else may be
using the card.
