# Audit, 2026-10-21

A code audit of `main` at e8863ca. It covers correctness, dead code,
duplicated logic, weak tests and performance across `mcp/`, `worker/` and
`web/`. Four reviewers each took one area: the ingest side, the query side,
HTTP and auth, and the worker with the web front end. Each reviewer reproduced
its findings with a scratch test before reporting them. Every fix then landed
with a regression test that fails on the code before it and passes after.
Before merging, a second agent that had not written the fix tried to break it.

Security findings are recorded in the private security repository, which is
the convention `docs/security.md` describes. This file names them only once
they are fixed.

Severity: **P0** is a bug in normal use. **P1** is a bug in an edge case, or
clear maintenance debt. **P2** is minor.

## Open

These are on `docs/ROADMAP.md`. Each one needs a decision before it is a ticket.

- **I5. A long multi-item job starves follow checks and the nightly ticks.**
  `_drive` never calls `before_claim` between items, which contradicts
  following.md. The smallest fix is to yield between items when a more urgent
  job is due. It changes scheduling, so it is a proposal.
- **W4. 0-MB slots (Voxtral STT, CPU OCR) queue behind the GPU lock.** Query
  embeddings wait behind minutes-long Voxtral jobs, and searches fall back to
  FTS. The smallest fix is a second lane for `vram_estimate_mb == 0`, which
  changes the `/status` shape and shutdown.
- **W9 remainder.** Uploads are still copied twice, because Starlette spools
  them first. There is no upload size cap, since that needs a new env var.
- **CI.** Nothing checks `worker/openapi.json` against the code. Suggested
  step: `make openapi && git diff --exit-code worker/openapi.json`.
- `follows/store.py` matches titles with an unescaped `LIKE`, the same
  problem as Q13.
- The web search views page by `offset + limit`, and the facade drops
  `truncated.next_offset`. Since Q5 a capped page keeps fewer than `limit`
  results, so the next page would skip the dropped ones. No shipped setting
  reaches the cap: the public box is 20 × 400 characters, and the feed uses
  300. An owner's hand-made URL can.
- `editions.MAX_RESPONSE_CHARS` is a second response cap. It is documented in
  aie-paris-2026.md, so it was kept.
